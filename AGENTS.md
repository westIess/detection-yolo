## Что это за проект

PPE Detection — компьютерное зрение для контроля СИЗ и опасных зон на стройплощадке.

- Детекция людей и предметов СИЗ: **YOLO11**.
- Трекинг людей между кадрами: **ByteTrack** (`ultralytics`).
- Проверка каски/жилета по истории наблюдений, опасная зона, журнал событий.
- Сохранение событий: JPG-снимок + JSON, экспорт журнала в JSONL.
- Модели: **v1** — YOLO11n / Construction-PPE (11 классов); **v2** — YOLO11s / SH17 (17 классов). Рабочая модель приложения — **v2**.
- Git: `https://github.com/westIess/detection-yolo.git`, ветка `main`.

Целевая архитектура включает FastAPI-пульт оператора, но в текущей папке веб-часть **отсутствует** (см. ниже).

## Логика, которую нельзя ломать без явной задачи

- Рабочая схема классов — SH17 (v2), ID 0–16: `person, ear, ear-mufs, face, face-guard, face-mask, foot, tool, glasses, gloves, helmet, hands, head, medical-suit, shoes, safety-suit, safety-vest`.
- Отсутствие детекции предмета само по себе не доказывает отсутствие СИЗ.
- Уведомление о возможном отсутствии каски/жилета: минимум **2 секунды и 5 наблюдений**.
- Повтор события для пары «ID человека / тип» — не чаще раза в **5 секунд**.
- Опасная зона проверяется по **нижней центральной точке** рамки человека. Слишком мелкие рамки (меньше 2 % ширины, 6 % высоты или 0,2 % площади кадра) не считаются человеком для алерта. Событие требует непрерывного нахождения в зоне **0.5 секунды и 5 наблюдений**; выход или разрыв трека сбрасывает подтверждение. Время — видео (`frame/fps`), не скорость обработки.
- `Events` — число уведомлений, а не уникальных нарушений.
- Без `--zone-file` проверка зоны отключена.

## Правила работы

1. **Сначала читай актуальные исходники** (`videores.py`, `README.md`, `WEB_SETUP.md`) — версии и структура могли измениться. Не полагайся на этот файл как на единственный источник.
2. **Не меняй установленные Torch/CUDA** и не переустанавливай пакеты без отдельной задачи.
3. **Не запускай обучение** (`YOLO.train`, `yolo detect train`) автоматически — только по прямой просьбе.
4. **Не трогай веса** (`*.pt`, `*.onnx`) без отдельной задачи; не перезаписывай `best_v2.pt`.
5. **Git:** не делай `git commit`, `git push`, `reset`, `checkout`/`restore` без запроса. В рабочем дереве есть незакоммиченные и untracked файлы пользователя — не откатывай их.
6. **Не добавляй в Git** видео, веса, `screenshots/violations/`, `zone.json`. Сейчас `zone.json` и `screenshots/violations/` в `.gitignore` не внесены — при коммите предупреди пользователя, но не меняй `.gitignore` без просьбы.
7. **Не удаляй незнакомые файлы** (`runs/`, `docs/`, `screenshots/`, `from pathlib import Path.py`) — это результаты экспериментов пользователя.
8. **После правок** объясни: что и зачем изменено, какие проверки реально выполнены и их результат. Если проверку не запускал — скажи это явно, не выдавай предположение за факт.
9. Держись стиля существующего кода: компактный Python, `Path`, `argparse`, без лишних зависимостей.
